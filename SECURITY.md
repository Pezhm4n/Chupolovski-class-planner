# Security Policy 🔐

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | ✅ Yes             |
| < 1.0   | ❌ No              |

## Reporting a Vulnerability

**Please do NOT report security vulnerabilities through public GitHub Issues.**

If you discover a security vulnerability in this project, report it responsibly:

- 📧 **Email:** [pksarmadi@gmail.com](mailto:pksarmadi@gmail.com)
- 📌 Subject: `[SECURITY] Golestoon Desktop — <short summary>`

Please include:

1. A description of the issue and its potential impact
2. Step-by-step instructions or a proof-of-concept
3. Affected version / commit hash
4. Any suggested mitigations (optional, appreciated)

### What to expect

- Acknowledgement within **72 hours**
- An assessment and severity rating within **7 days**
- Credit in the release notes (if you wish)

## Scope & Rules (بازه و قوانین)

This repository contains the **desktop client only**. The backend services are
out of scope of this repository — but responsible reports about issues you can
demonstrate through the desktop client's communication with the public API are
welcome.

**Allowed:**
- Testing against your own account and data
- Issues in this client's code (injection, credential handling, unsafe parsing…)

**NOT allowed (و مجاز نیست):**
- Any form of Denial-of-Service, spam, or automated bulk requests against the services
- Accessing, modifying, or enumerating other users' data
- Social engineering, phishing, or physical attacks
- Testing on accounts you do not own

Violating these rules may result in permanent blocking and legal action.

## Safe Harbor

We consider security research done in good faith, within the rules above, in
the spirit of coordinated disclosure. We will not pursue legal action against
researchers who respect this policy.
